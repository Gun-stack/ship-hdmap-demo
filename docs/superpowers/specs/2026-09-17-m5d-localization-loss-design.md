# M5d 설계 스펙 — 측위 상실 판정과 역추적 회복 (2026-09-17)

기본 스펙 `2026-09-15-ship-hdmap-demo-design.md` 의 M5c 다음에 넣는 단계다. 브레인스토밍에서 확정한 결정만 담는다. 용어는 [용어집](../../glossary.md), 선택 근거는 [설계 근거](../../design-rationale.md) 참조.

- **M5c (앞)**: 갑판의 어느 지점에서 어느 정도 정밀도가 가능한지 계산하고 마커 배치를 추천한다
- **M5d (이 문서)**: 그 예측을 차량에 들려 보내고, 예측보다 나빠지면 알아채고, 자취를 되짚어 빠져나오게 한다
- **M6 (다음)**: 문서·시연

---

## 1. 범위

### 1.1 목적

[설계 근거](../../design-rationale.md) 요약 7번이 **"어려운 것은 측위가 아니라 실패 회복이다"** 라고 적어 두었고, §6.6 의 표에서 `측위 상실 | 빈도 흔함 | 오도메트리로 짧게 버팀 → 초과 시 정지` 한 줄이 아직 하나도 구현돼 있지 않다.

지금 코드는 마커가 하나도 안 보이면 이렇게 한다:

```csharp
return new LocalizerResult { ok = false, pose = previous ?? default, nObs = 0 };
```

**차가 옛 믿음을 그대로 붙들고 계속 달린다.** 얼마나 오래 잃었는지도, 얼마나 나쁜지도 모르고, 아무 행동도 하지 않는다.

M5c 가 이 단계의 표적을 측정해서 넘겨주었다 — Deck 3 바깥 열 구획의 68.5 % 가 선적 모드에서도 `blind` 다. 차를 거기로 보내면 **반드시** 측위를 잃는다. 지도 위에서 예측한 지점에서 실제로 차가 멈추는 것을 보이는 것이 이 단계의 그림이다.

### 1.2 들어가는 것

1. `Localizer` 가 자세와 함께 **달성한 σ** 를 낸다 (정보행렬의 역, `CoverageAnalyzer` 와 같은 수학)
2. 차량이 주행 전 커버리지를 한 번 받아 **예측 σ 격자**를 들고 다닌다
3. 상태 기계: `OK` / `DEGRADED`(예측보다 나쁨) / `LOST`(관측 0)
4. `LOST` 동안 오도메트리로 버티되 불확실성 예산을 쓴다
5. 예산 초과 시 **역추적** — 측위가 좋았던 자취를 되짚어 후진
6. 회복 실패 시 정지, 그 구획을 `unreachable` 로 표시하고 다음 구획으로
7. 마커 가림 토글 — 훼손·적재 차폐를 손으로 만들어 저하 판정을 확인한다

### 1.3 제외

- **다중 차량.** §6.6 의 "뒤차 전부 정지"는 여러 대가 있어야 의미가 있다. 한 대로도 상실·정지·스킵은 전부 보인다
- 통신 두절, AEB. 측위와 다른 층위의 실패다
- 선회하며 재탐색. 회복은 역추적 하나뿐이다 — 지나온 길은 이미 안전이 확인된 유일한 경로다
- **구간별 허용오차.** §3.3 의 측정이 전제를 부정했다
- 지도 오차(측량 오차) 모델. 파킹 유지 ([설계 근거](../../design-rationale.md) §7.1, 그리고 §3.3 의 측정 참조)
- 오도메트리의 정밀 모델. 이동 거리 비례 drift 한 항으로 끝낸다

### 1.4 완료 기준

차량이 측위를 잃는 자리는 **하역 이탈 구간의 선미**다. Deck 3 의 차로 위 `x 0 ~ 18` 은 하역 방향(ψ=180)에서 마커가 하나도 잡히지 않는 **18.5 m** 짜리 사각지대이고, M5c 가 지도만 보고 찾아낸 바로 그 구간이다. 이탈 경로가 배를 빠져나가며 여기를 통과한다.

브라우저에서 확인된 연쇄:

| 단계 | 실측 |
| --- | --- |
| 차로 정상 주행 | 실측 σxy 0.26 m = 예측 0.26 m (1.0 배) |
| 선미 진입 | 마커 0 개, 예측은 여전히 0.76 m 를 약속 |
| 오도메트리 버팀 | 13.3 m 주행, `σ_odo` 0.67 m (예산 1.0 m) |
| 역추적 | 거리 한계 5 m 초과 후 후퇴 |
| 정지 | 자취 소진 |
| 포기 | 재시도 1 회 후 `unreachable`, 다음 구획으로 |

**`σ` 실측과 예측의 일치가 이 단계의 중심 증거다.** `Localizer` 와 `CoverageAnalyzer` 가 같은 정보행렬·같은 야코비안을 쓰므로, 주행이 지도의 예측을 그 자리에서 검산한다. 어긋나면 지도에 없는 무언가가 있다는 뜻이다.

**바깥 열 구획은 차를 세우지 않는다.** M5c 는 바깥 열(`|y| ≈ 10.1`) 셀의 68.5 % 가 선적 모드에서 `blind` 라고 쟀고 그것은 참이지만, 차가 그 띠를 지나는 **경로**에서는 마커가 보였다 — `PS-D3-001`(`y = −10.08`, `sequence_no` 1)은 `lat` 오차 0.03 m 로 정상 주차했다. **셀의 blind 비율과 경로 위에서 겪는 상실은 같은 것이 아니다.** 커버리지는 "어디가 나쁜가"를 답하고, 주행은 "이 길로 가면 실제로 어떻게 되는가"를 답한다. 둘을 겹쳐 봐야 하는 이유가 여기 있다.

## 3. 모델

### 3.1 달성한 σ

`Localizer.Solve` 는 이미 매 반복마다 정보행렬을 쌓는다. 야코비안이 `CoverageAnalyzer` 와 **글자 그대로 같다**:

```csharp
double[] jr = { -res.dx / res.rh, -res.dy / res.rh, 0 };
double[] jt = { res.dy / (res.rh * res.rh), -res.dx / (res.rh * res.rh), -1 };
double[] ja = { 0, 0, -1 };
```

수렴 후의 `A` 를 역행렬 하면 `σ_xy = √(C₀₀+C₁₁)`, `σ_psi = √(C₂₂)` 다. `Solve3` 가 이미 있는 크라메르 풀이라 3×3 역행렬만 더하면 된다. `LocalizerResult`(`Observation.cs`)는 필드 다섯의 평범한 클래스라 둘을 더하는 데 걸리는 것이 없다.

**같은 수학을 두 곳이 쓰는 것이 이 단계의 값어치다.** 커버리지가 "여기선 σxy 0.99 m 일 것"이라 예측하고, 주행이 "실제로 0.97 m"라고 답한다. 두 숫자가 어긋나면 지도에 없는 무언가가 있다는 뜻이다.

`nObs = 0` 이면 σ 는 `null` 이다 — M5c 의 `blind` 와 같은 처리다.

### 3.2 예측 σ 격자

시나리오 시작 시 `POST /api/datasets/{ds}/decks/{deck}/coverage` 를 **한 번** 호출해 `cells` 를 들고 있는다. `grid_m` 1.0 이면 Deck 3 이 2,880 셀, 약 200 KB — WebGL 에서 부담이 없다.

`in_scope` 가 아닌 셀도 그대로 쓴다. 차는 구획·차로 밖으로도 밀려날 수 있고, 그때야말로 예측이 필요하다.

조회는 최근접 셀이다. 격자가 1 m 라 셀 안에서의 변화는 판정 배수(§3.3)보다 훨씬 작다.

모드는 주행 방향을 따른다 — 선적이면 `load`, 하역이면 `unload`. §3.5 의 이유로 둘의 예측이 크게 다르다.

### 3.3 왜 주차 허용오차를 기준으로 쓰지 않는가

처음에는 구간별 허용오차(차로는 느슨, 마지막 5 m 는 빡빡, [설계 근거](../../design-rationale.md) 요약 5번)를 임계값으로 쓰려 했다. **측정이 그 전제를 부정했다.**

Deck 3, 선적, 기본 센서, 지도 완벽:

| 구간 | 셀 | blind | σxy 중앙 | σxy 90 % | σψ 중앙 |
| --- | --- | --- | --- | --- | --- |
| 차로 | 476 | 1.7 % | **0.280 m** | 0.704 m | 0.979° |
| 진입 (구획 5 m 이내) | 1,440 | 37.1 % | **0.754 m** | 0.962 m | 2.000° |
| 구획 안 | 760 | 26.3 % | **0.538 m** | 0.942 m | 2.000° |

**구획 안이 차로보다 두 배 나쁘다.** 구획은 마커 줄(`y = ±6.2`)에서 멀어 더 적은 마커를 더 나쁜 각도로 본다. "마지막 5 m 에서 정밀도가 좋아진다"는 전제가 이 지도에서는 성립하지 않으므로, 거기서 기준을 조이면 구획이 전부 실패로 바뀔 뿐이다.

여러 구간에서 `σψ` 가 정확히 `2.000°` 인 것은 **보이는 마커가 1 개**라는 뜻이다 — `ja = {0,0,−1}` 한 줄만 남아 `σψ = σ_α` 가 된다.

그리고 M5c 의 `weak` 가 포화된 것(비-blind 1,028 셀 **전부** `stability < 1`, 최댓값 0.897)은 지표의 결함이 아니라 **사실의 보고**였다. 이 지도는 어디서도 0.15 m 를 못 낸다.

### 3.4 판정

기준은 **지도가 약속한 값**이다.

```
관측 0                            → LOST
실측 σxy > k × 예측 σxy (연속 N)   → DEGRADED
그 외                             → OK
```

기본값 `k = 2.0`, `N = 5` 프레임. 둘 다 `DrivePanel` 슬라이더다.

이 기준을 쓰는 이유:

- **지도의 실력에 자동으로 맞춰진다.** 차로에서는 0.28 m 를 기대하고 구획에서는 0.54 m 를 기대한다. 고정 임계값 하나로는 둘 다 맞출 수 없다
- **지도에 없는 문제를 잡는다.** 마커 훼손, 적재된 차에 의한 가림 — [설계 근거](../../design-rationale.md) §7 이 "마커는 항상 보인다 / 현실은 적재·훼손으로 가려짐"으로 파킹해 둔 항목이다
- **M5c 없이는 불가능하다.** 예측치가 있어야 "약속보다 나쁘다"를 말할 수 있다

예측 자체가 `blind` 인 셀에서는 `DEGRADED` 를 판정하지 않는다 — 비교 대상이 없고, 어차피 `LOST` 로 들어간다.

### 3.5 오도메트리 예산

`LOST` 동안 차는 명령한 운동을 적분해 자세를 밀고 나간다. 불확실성은 이동 거리에 비례해 자란다:

```
σ_odo = drift_rate × (LOST 진입 후 이동 거리)
```

기본 `drift_rate = 0.05` (5 %/m), 슬라이더. 예산은 두 가지로 끊는다:

| 한계 | 기본값 | 이유 |
| --- | --- | --- |
| `σ_odo > budget_m` | 1.0 m | 차로 폭 3.2 m 의 절반 이하 — 아직 차로 안이라고 믿을 수 있는 선 |
| 이동 거리 > `max_lost_m` | 5.0 m | 시간이 아니라 거리로 끊는다. 속도를 바꿔도 같은 곳에서 멈춘다 |

**두 한계는 역할이 다르다** (M5d 구현 중 발견, Task 5 리뷰로 확정). `σ_odo > budget_m` 은 추측항법 자체를 더는 믿을 수 없다는 뜻이라 **항상 정지**로 간다 — 역추적을 벌지 않는다. `이동 거리 > max_lost_m` 은 **경로당 한 번만** 역추적을 시작시킨다. 같은 경로에서 두 번째로 이 거리를 넘기면 역추적하지 않고 눈을 감은 채 전진을 계속한다(push through) — 지나갈 수 없는 공백을 만나면 후퇴→복귀→같은 공백 재진입이 끝없이 반복되는 livelock 이 되기 때문이다. 경로가 바뀌면(`BeliefMonitor.Reset()`) 그 경로는 다시 한 번의 역추적 기회를 얻는다.

기본값 5 %/m 에서 예상되는 거동: 5 m 눈멀면 첫 역추적 → 복귀 → 같은 공백을 다시 만나면 이번엔 통과 → 공백 너머에서 관측이 돌아온다. 그 공백이 20 m 보다 넓어서 σ_odo 가 예산(1.0 m)을 넘기면 그때는 정지한다. drift 를 20 % 이상으로 올리면 첫 손실에서부터 σ 한계가 먼저 걸려 곧장 정지한다 — 역추적을 한 번도 벌지 못하고 멈추는 경우다.

### 3.6 역추적

`OK` 였던 동안의 호길이 `s` 를 링버퍼에 넣는다 — `VehicleController` 가 이미 `s` 로 매개화돼 있고 `Rewind(s)` 를 갖고 있다. 기록 간격 0.25 m, 길이 `trail_m` 20 m (기본).

```
거리 한계 초과, 이 경로에서 첫 역추적 → 자취를 역순으로 후진 (전진 속도의 1/2)
  ├ 도중에 관측이 돌아오면        → 재측위 → OK → 전진 재개 (이 경로의 역추적은 소진됨)
  └ 자취를 다 쓰면                → 정지
같은 경로에서 다시 거리 한계 초과 → 역추적하지 않고 전진 계속 (push through)
σ_odo 가 예산을 넘기면 (언제든)   → 정지
```

후진 중에도 오도메트리로 자세를 민다. 자취는 **이미 지나온 길**이라 장애물이 없는 것이 확인된 유일한 경로이고, 그래서 못 믿을 자세로도 따라갈 수 있다. 자취의 형상만 따라가면 되고 절대 좌표는 필요 없다.

**M5c 가 회복 거리를 예측한다.** 커버리지 격자에서 현재 위치로부터 자취를 거슬러 가며 처음으로 `n ≥ 1` 인 셀이 나오는 지점까지의 거리가 곧 예상 회복 거리다. HUD 에 같이 띄워 예측과 실제를 나란히 본다.

### 3.7 실패 처리

정지하면 그 구획을 시도 실패로 센다.

| 시도 | 결과 |
| --- | --- |
| 1 회차 | 차로 복귀 후 재시도 |
| 2 회차 | 구획 `status = 'unreachable'`, 다음 구획으로 |

`unreachable` 은 `parking_slot.status` 의 새 값이다. 현재 제약이 `CHECK (status IN ('empty','filled','needs_adjust'))` 라 마이그레이션 `V2__unreachable.sql` 이 필요하다 — 이 프로젝트의 첫 V2 다.

`ScenarioPlanner.IsFilled` 는 `unreachable` 도 참으로 본다(다시 고르지 않는다). 평면도·3D 에서는 `needs_adjust` 의 주황과 구분되는 회색으로 칠한다.

## 4. 브리지 메시지

기존 `.jslib` 브리지에 셋을 더한다.

| 방향 | 이름 | 내용 |
| --- | --- | --- |
| 웹 → Unity | `SetBeliefParams` | `{ k, frames, drift_rate, budget_m, max_lost_m, trail_m }` |
| 웹 → Unity | `SetOccluded` | `{ ids: ["LM-0003", …] }` — 센서가 무시할 마커 |
| Unity → 웹 | `onBelief` | `{ state, sigma_xy, sigma_psi, predicted_sigma_xy, n_obs, lost_m, recovery_m }` |

`onBelief` 는 기존 `onLocalization` 과 같은 0.2 초 주기로 내보낸다. 별도 주기를 만들지 않는다.

`SetOccluded` 는 DB 를 건드리지 않는다 — M5c 의 `omit` 이 계산에서만 빼는 것과 같은 성격이고, 훼손은 지도의 사실이 아니라 그 순간의 사정이다.

## 5. 웹

### 5.1 DrivePanel

기존 노이즈 슬라이더 아래에 한 구역을 더한다. 슬라이더는 **놓을 때만** 호출한다(기존 `SetNoise` 와 같은 이유).

| 항목 | 내용 |
| --- | --- |
| 상태 | `OK` / `저하` / `상실` / `역추적` 배지, 색으로 구분 |
| 숫자 | 실측 σxy · 예측 σxy · 배수, 보이는 마커 수 |
| 파라미터 | `k`, `N` 프레임, drift %, 예산 m, 최대 상실 m, 자취 m |
| 회복 | 상실 후 이동 거리, 예상 회복 거리(M5c 예측), 실제 회복 거리 |
| 집계 | 도달 / 도달 불가 구획 수 |

### 5.2 마커 가림

`LayerTree` 의 LM 항목에 체크박스를 더한다. 끄면 `SetOccluded` 로 전달되고, 평면도에서 그 마커를 회색으로 칠한다.

M5c 의 `omit`(커버리지 계산에서 제외)과 **같은 체크박스를 쓴다.** 하나를 끄면 커버리지 예측과 센서가 동시에 그 마커를 잃는다 — 그래야 "예측이 이미 나쁠 것이라고 말한 곳에서 실제로 나쁘다"가 되고, 예측과 실제가 어긋나는 것이 아니라 함께 움직이는 것을 보게 된다.

훼손을 **예측에는 반영하지 않고** 센서에서만 빼는 실험은 별도 토글로 둔다 — 그때가 `DEGRADED` 가 진짜 일하는 장면이다.

## 6. 테스트

### 6.1 단위 (Unity EditMode)

1. **σ 가 나온다** — 마커 2 개로 `Solve` 하면 `sigmaXy` 가 유한하고 양수다. 같은 배치에 대해 `CoverageAnalyzer` 의 예측과 **10 % 이내로 일치**한다 (두 구현이 갈라지지 않았다는 확인)
2. **관측 0 이면 σ 가 null 이고 상태가 LOST**
3. **예측보다 나쁘면 DEGRADED** — 실측이 예측의 2.5 배이고 `N` 프레임 이어지면 전이한다. `N−1` 프레임에서는 전이하지 않는다
4. **예측이 blind 면 DEGRADED 로 안 간다** — LOST 로 간다
5. **오도메트리 예산** — 거리 한계는 역추적으로, σ 한계는 정지로 간다 (역할이 다르다, §3.5)
6. **역추적이 자취를 역순으로 낸다** — 기록 간격보다 촘촘히 물어도 단조롭게 뒤로 간다
7. **자취를 다 쓰면 정지**
8. **경로당 역추적은 한 번** — 같은 경로에서 두 번째로 거리 한계를 넘기면 역추적하지 않고 전진을 계속한다(push through); 그 상태에서 σ 예산을 넘기면 정지한다
8. **회복 성공** — 후진 중 관측이 돌아오면 OK 로 복귀하고 자취 소비가 멈춘다
9. **가려진 마커는 감지되지 않는다** — `SetOccluded` 후 `nObs` 가 준다

### 6.2 회귀 (Unity EditMode)

**바깥 열 구획에서 반드시 잃는다.** 픽스처의 Deck 3 에서 `|y| > 9` 인 구획을 목표로 주면 `LOST` 를 거친다. M5c 의 회귀(`theOuterSlotRowIsBlindEvenWhenLoading`)와 짝이다 — 한쪽은 지도 위에서, 한쪽은 주행으로 같은 결함을 고정한다.

**차로에서는 잃지 않는다.** 차로만 달리는 시나리오는 끝까지 `OK` 다 (차로 blind 1.7 %).

### 6.3 API

1. `unreachable` 이 저장되고 조회된다
2. 알 수 없는 status 는 400

### 6.4 웹 (Vitest)

1. 상태 → 배지 색·라벨 매핑
2. 배수 표시 포맷 (예측 대비 몇 배)

### 6.5 브라우저 검증

1. 차로 주행 중 상태가 `OK`, 실측 σ 가 예측 σ 근처
2. 바깥 열 구획을 목표로 주면 `저하` → `상실` 로 바뀐다
3. 예산을 다 쓰면 후진이 시작되고 차로에서 `OK` 로 복귀한다
4. 2 회차 실패 후 그 구획이 회색(`unreachable`)이 되고 다음 구획으로 넘어간다
5. 시나리오 끝에 도달 불가 수가 표시되고, M5c 의 바깥 열 예측과 같은 방향이다
6. 마커 하나를 가리면 커버리지 히트맵과 주행 상태가 **함께** 나빠진다
7. 예측에는 반영하지 않고 센서에서만 빼면 `저하` 가 뜬다
8. `drift` 를 20 % 로 올리면 거리 한계가 아니라 σ 한계가 먼저 걸린다

## 7. 결정과 이유

| 결정 | 이유 |
| --- | --- |
| 임계값을 지도의 예측으로 | 고정 임계값 하나로는 차로(0.28 m)와 구획(0.54 m)을 같이 맞출 수 없다. 예측 대비 배수는 지도의 실력에 자동으로 맞춰진다 |
| 구간별 허용오차를 뺌 | 측정이 전제를 부정했다 — 구획이 차로보다 두 배 나쁘다(§3.3). "마지막 5 m 에서 좋아진다"가 이 지도에서는 거짓이다 |
| σ 를 `Localizer` 에서 | A 행렬이 이미 있다. 야코비안이 `CoverageAnalyzer` 와 같아서, 두 구현의 일치 자체가 테스트가 된다 |
| 회복을 역추적으로만 | 잃은 상태에서 새 경로를 짜려면 못 믿을 자세를 믿어야 한다. 지나온 길은 안전이 확인된 유일한 경로이고, 형상만 따라가면 되어 절대 좌표가 필요 없다 |
| 예산을 거리로 (시간 아님) | 속도를 바꿔도 같은 곳에서 멈춘다. 시연에서 재현된다 |
| 예측 격자를 한 번만 받음 | Ship Frame 이 불변이라 주행 중 예측이 변하지 않는다. 마커를 저장하거나 가릴 때만 다시 받는다 |
| 가림을 DB 에 안 씀 | 훼손은 지도의 사실이 아니라 그 순간의 사정이다. M5c 의 `omit` 과 같은 성격 |
| `unreachable` 을 새 status 로 | `needs_adjust` 는 "댔는데 삐뚤다"이고 이건 "가지도 못했다"다. 평면도에서 구분돼야 원인이 보인다 |
| 다중 차량 없음 | "뒤차 전부 정지"는 여러 대가 필요하지만, 상실·회복·스킵은 한 대로 전부 보인다. 다중 차량은 이 위에 얹는 일이다 |

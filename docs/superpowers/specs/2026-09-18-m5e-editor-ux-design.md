# M5e 설계 스펙 — 편집기로 쓸 수 있게 (2026-09-18)

기본 스펙 `2026-09-15-ship-hdmap-demo-design.md` 의 M5d 다음에 넣는 단계다. 브레인스토밍에서 확정한 결정만 담는다. 용어는 [용어집](../../glossary.md), 선택 근거는 [설계 근거](../../design-rationale.md) 참조.

- **M5d (앞)**: 차량이 측위 품질을 알고, 잃으면 되짚어 나오고, 못 나오면 구획을 포기한다
- **M5e (이 문서)**: 그 전부를 **사람이 조작할 수 있는 편집기**로 만든다
- **M6 (다음)**: 문서·시연

---

## 1. 범위

### 1.1 목적

M1~M5d 가 기능을 쌓는 동안 화면은 기능마다 패널이 하나씩 늘어나는 방식으로 자랐다. 지금 편집 모드의 오른쪽에는 패널 넷이 세로로 쌓여 있고, 평면도는 왼쪽 칼럼 맨 아래에 세로로 눌려 있으며, **3D 에서 아무 데나 클릭하면 마커가 생긴다.**

마지막 것이 특히 나쁘다. `LandmarkPlacer` 의 주석이 그대로 말한다 — "left click on ship structure spawns a marker". 카메라를 돌리려고 빈 곳을 클릭할 수가 없다. 도구 모드가 없기 때문이다.

M5e 는 기능을 더하지 않는다. **이미 있는 기능을 사람이 쓸 수 있게 만든다.**

### 1.2 들어가는 것

1. **배치**: 평면도를 하단 도크로(전폭), 오른쪽을 탭으로
2. **독해**: 히트맵 범례, 숫자에 분모 병기, 마커 법선과 라벨을 화면에
3. **도구 모드**: 선택 / 배치 / 관측 — 클릭이 무엇을 하는지 사람이 정한다
4. **선택**: 3D·트리·평면도 세 곳 동기화, 선택 시 속성 탭 자동 전환, 카메라 프레이밍
5. **법선 편집**: 3D 기즈모와 숫자 입력. 바꾸면 커버리지가 다시 계산된다
6. **카메라**: 궤도 / 자유 비행(`WASD`) / 차량 시선
7. **가상 관측점**: 편집 중에 "여기서 뭐가 보이나" 를 눈으로 확인한다
8. **뷰포트**: 3D·평면도 각자 확대·이동
9. **단축키**
10. **상태 저장**: `localStorage`

### 1.3 제외

- **3D 히트맵 오버레이.** M5c 가 명시적으로 제외했다 — 커버리지는 3D 로 **계산**하되 2D 로 **표시**하면 충분하다. 뒤집지 않는다
- **되돌리기(undo).** DB 쓰기를 가로지르는 undo 는 별개 마일스톤 규모다. 삭제를 버튼으로만 두는 것이 실질적 안전장치다
- **`Delete` 키로 삭제.** 되돌릴 수 없는 동작치고 너무 쉽다. 삭제는 속성 패널 버튼 하나뿐
- **다중 선택·일괄 편집.** 법선을 여럿 한 번에 돌리고 싶어지면 그때 넣는다
- **새 배치 경로** — 평면도 클릭 배치, 좌표 입력, 복제·미러링. 이번 축은 "놓은 뒤 고치기"다
- **DB·URL 상태 저장.** 화면 상태는 보는 사람의 것이므로 브라우저에 둔다
- **카메라 북마크, 거리 측정 자, 스크린샷 버튼, 시나리오 로그 되감기**

### 1.4 완료 기준

1. 새로고침해도 탭·갑판·모드·슬라이더·카메라·도크 높이가 그대로다
2. 히트맵을 **확대 없이** 읽고, 범례가 색과 분모를 설명한다
3. 트리에서 마커를 고르면 3D 카메라가 그리로 가고, 3D·트리·평면도가 같은 선택을 보인다
4. **3D 에서 법선을 돌려 저장하면 커버리지 숫자가 그에 따라 바뀐다** — M5c·M5d 가 "법선이 결정적"이라 말해놓고 고칠 길이 없던 고리가 닫힌다
5. **편집 모드에서 3D 를 마음대로 클릭·회전해도 마커가 생기지 않는다.** 배치는 배치 모드에서만 일어나고, 그 모드가 켜져 있다는 것이 화면에 보인다
6. 차량 시선으로 하역을 돌리면 선미 구간에서 **마커가 하나씩 꺼지고**, 마지막 하나가 꺼지는 시점이 믿음 상태가 `상실` 로 바뀌는 시점과 같다
7. 편집 중 갑판 위에 관측점을 찍으면 그 자리에서 보이는 마커와 안 보이는 마커가 구분되고, 시야 콘 밖·사거리 밖·법선이 등을 돌린 경우가 각각 다른 이유로 꺼진 것이 읽힌다

## 3. 배치와 독해

### 3.1 하단 도크

갑판은 120 × 24 m 로 **5:1 가로 그림**이다. 지금은 좁은 왼쪽 칼럼 맨 아래에 눌려 있어 히트맵을 확대하지 않고는 읽을 수 없다. 전폭 하단 도크로 내린다.

- 접기/펴기, 높이 2단(보통 / 크게)
- 휠 확대, 드래그 이동, `F` 로 선택 맞춤, `0` 으로 전체
- 왼쪽 칼럼은 트리만 남아 짧아진다

### 3.2 오른쪽 탭

`적재 / 커버리지 / 속성 / 자세` 중 **하나만** 연다. 지금은 넷이 세로로 쌓여 pose 슬라이더를 보려면 스크롤해야 한다.

**선택이 일어나면 `속성` 탭으로 자동 전환한다.** 탭으로 묶으면서 이걸 빠뜨리면 지금보다 나빠진다 — 세로로 쌓였을 때는 속성이 우연히 보였기 때문이다. 선택을 해제하면 원래 보던 탭으로 돌아온다.

### 3.3 읽히게

- **히트맵 범례** — 색 띠와 `blind / weak / ok`, 그리고 out-of-scope 셀이 흐린 이유("차가 갈 일이 없어 숫자에서 뺐다")
- **숫자에 분모를 붙인다** — `16.8 %` 가 아니라 `16.8 % (구획·차로 1,236 셀 중)`. M5c 에서 배운 것이다. 분모를 안 보이면 갑판 전체로 오해한다
- **마커 법선을 항상 그린다** — 평면도와 3D 양쪽. M5c 는 **후보** 마커에만 화살표를 그렸고 저장된 마커에는 안 그렸다. 법선 기즈모를 넣는 마일스톤에서 그 효과가 안 보이면 절반만 만든 것이다
- **마커 라벨** — 확대하면 `LM-0003` 이 뜬다. 지금은 클릭해 속성을 봐야 어느 것인지 안다

## 4. 편집기

### 4.1 도구 모드

| 모드 | 키 | 클릭 | 드래그 |
| --- | --- | --- | --- |
| **선택** (기본) | `V` | 마커 선택 / 빈 곳은 선택 해제 | 마커 이동 |
| **배치** | `A` | 구조물 면에 마커 생성(면 법선 방향) | — |
| **관측** | `P` | 갑판에 관측점을 찍는다 (§5.3) | — |

**배치 모드는 고정(sticky)이다.** 한 번 놓고 선택으로 돌아가는 방식도 있지만, 마커를 줄지어 놓는 것이 이 지도의 실제 작업이다(12 m 간격 18 개). 대신 **모드가 켜진 것을 숨기지 않는다** — 툴바 강조, 커서 변경, 3D 가장자리 테두리. 우발적 생성의 원인은 "모드가 고정이라서"가 아니라 "모드가 있는 줄 몰라서"다.

`Esc` 는 언제나 선택 모드로 돌아오고 선택을 해제한다.

### 4.2 선택

3D·트리·평면도가 **같은 선택을 보인다.** 어디서 고르든 나머지 둘이 따라온다.

3D 강조는 지금 마커 뒤에 Quad 하나(Halo)를 붙이는 방식이다. 윤곽선과 완만한 펄스로 바꿔 멀리서도 눈에 띄게 한다. 그리고 **`F` 로 카메라가 선택으로 간다** — 이것이 "강조"의 실질이다. 지금은 하이라이트만 켜지고 화면 밖이면 보이지 않는다.

### 4.3 법선 편집

M5c·M5d 가 **법선이 위치보다 결정적**이라고 반복해서 밝혔다. 그리디가 고르는 면도 전부 법선이 다른 면이었고, 선미 끝단 마커 둘은 법선이 갑판 밖을 향해 어느 지점에서도 보이지 않는다. 그런데 지금 법선을 바꾸려면 `props` JSON 을 손으로 고쳐야 한다.

- **3D 기즈모** — 선택한 마커 둘레의 원형 핸들. 끌면 법선이 돌고, 놓으면 저장한다
- **속성 패널 숫자 입력** — `φ` 를 도로 직접 친다. 기즈모와 같은 값을 본다
- 저장되면 **커버리지를 다시 계산**해 히트맵이 즉시 반응한다

### 4.4 삭제

**속성 패널의 삭제 버튼 하나뿐이다.** 이미 있는 경로이고(`PropertyForm`, DB 를 먼저 지우고 Unity 에 `Delete`), 바꾸지 않는다. 바뀌는 것은 **거기까지 가는 길**이다: 3D 에서 마커를 고르면 속성 탭이 자동으로 뜨고 그 마커가 채워져 있다.

`Delete` 키는 넣지 않는다(§1.3).

## 5. 카메라와 관측

### 5.1 모드 셋

`C` 로 순환하고 툴바에서도 고른다. 갑판 단축키가 `1 2 3` 을 쓰므로 카메라는 숫자를 쓰지 않는다.

| 모드 | 내용 |
| --- | --- |
| **궤도** (기본) | 지금 것 그대로. 우클릭 회전, 휠 확대, 차량 추적 |
| **자유 비행** | `WASD` + 방향키 이동, `Q`/`E` 상하, `Shift` 가속, 우클릭 드래그로 시선 |
| **차량 시선** | 눈높이 1.2 m, 차량 자세 `ψ` — 센서가 보는 그 자리. 주행 모드 전용 |

**입력 충돌.** `WASD` 는 자유 비행에서만 먹는다. `MapRuntime` 이 이미 `WebGLInput.captureAllKeyboardInput = false` 로 두어 웹이 키를 먼저 받으므로, 비행 키는 **3D 캔버스에 포커스가 있을 때만** 동작하고 그 상태를 테두리로 보인다.

### 5.2 차량 시선은 센서 시선이다

눈높이와 자세가 센서와 같으므로 그 화면이 곧 `LandmarkSensor` 가 보는 장면이다. 그래서 두 가지를 겹쳐 그린다.

**지금 감지 중인 마커를 밝게.** `MapRuntime._seen` 이 매 프레임 그 집합을 들고 있다. 지도에는 있지만 안 보이는 마커는 흐리게.

**시야 콘과 사거리 호를 갑판 바닥에.** 시야각 90° 경계 두 줄과 25 m 호. 그러면 마커가 꺼진 이유가 같은 화면에 있다:

| 보이는 것 | 뜻 |
| --- | --- |
| 콘 밖으로 나갔다 | 시야각 초과 |
| 호 너머다 | 사거리 초과 |
| **콘 안 호 안인데 꺼졌다** | 법선이 등을 돌렸거나 기둥에 가렸다 |

세 번째가 값어치 있다 — 눈에 안 보이는 두 조건이 소거법으로 드러난다.

M5d 의 숫자(`마커 0 개`)와 화면이 같은 이야기를 하게 된다. 선미 사각지대로 들어가면 마커가 하나씩 꺼지고, 마지막이 꺼지는 순간 믿음 상태가 `상실` 로 바뀐다.

### 5.3 가상 관측점

편집 중에 "여기서 뭐가 보이나" 를 확인한다. 마커를 놓고 나서 운전석 눈높이로 가보는 일이 자연스럽다.

- 관측 모드(`P`)에서 갑판을 클릭하면 그 자리, 눈높이 `z_surface + 1.2 m` 에 관측점이 선다
- 카메라가 그 자리로 가서 1인칭이 되고, 마우스나 방향키로 `ψ` 를 돌린다
- **차량 시선과 같은 표시**를 쓴다 — 보이는 마커는 밝게, 콘과 호를 바닥에
- 관측점은 하나뿐이다. 다시 클릭하면 옮겨간다. DB 에 저장하지 않는다

**가시 판정은 한 곳에서만 나온다.** `LandmarkSensor` 의 `Sense` 에서 가시성 부분을 `VisibleFrom(Pose2D, eyeHeight)` 로 뽑아 `Sense` 와 표시가 같은 구현을 쓴다. 세 조건과 기둥 차폐와 `occluded` 집합을 모두 같은 자리에서 본다. M5d 가 `Localizer` 와 `CoverageAnalyzer` 를 같은 야코비안으로 묶어 얻은 것과 같은 성질이다 — 두 구현이 갈라질 수 없다.

`_seen` 은 믿음 판정용으로 그대로 둔다. 표시는 `VisibleFrom` 을 쓴다.

### 5.4 단축키

| 키 | 동작 |
| --- | --- |
| `V` / `A` / `P` | 도구 모드 — 선택 / 배치 / 관측 |
| `C` | 카메라 모드 순환 — 궤도 → 자유 비행 → 차량 시선 |
| `W A S D` · 방향키 · `Q` `E` · `Shift` | 자유 비행 이동 (그 모드에서만, 캔버스 포커스 필요) |
| `F` | 선택에 맞춤 — **활성 뷰포트에만** |
| `0` | 전체 보기 — 활성 뷰포트에만 |
| `Esc` | 선택 해제 + 선택 모드로 |
| `1` `2` `3` | 갑판 D1 / D2 / D3 |
| `Tab` | 오른쪽 탭 순환 |
| `?` | 단축키 목록 |

`A` 가 배치 모드와 자유 비행의 왼쪽 이동에 겹치지만 충돌하지 않는다 — 비행 키는 자유 비행 모드에서 캔버스에 포커스가 있을 때만 읽고, 도구 모드 키는 그 밖에서만 읽는다. 겹치는 것이 불편해지면 도구 모드를 툴바 클릭으로만 두는 것이 물러설 자리다.

**입력 필드에 포커스가 있으면 단축키는 전부 먹지 않는다.** 속성 패널에서 `φ` 를 치다가 `0` 을 누르면 뷰가 리셋되는 일이 없어야 한다.

## 6. 상태 저장

`localStorage`, 데이터셋별 키, 스키마 버전 하나. 형식이 바뀌면 버리고 기본값으로 시작한다.

| 저장 대상 | |
| --- | --- |
| 열린 탭, 트리 펼침, 갑판, 모드(편집/주행) | 화면 구성 |
| 도구 모드, 카메라 모드, 도크 높이·접힘 | 편집기 상태 |
| 슬라이더 전부 — 노이즈·커버리지·믿음, 시간 배율 | 검증할 때마다 다시 맞추던 것 |
| 3D 카메라 자세, 평면도 확대·이동 | 뷰포트 |
| 마커 가림 집합 | §6.1 |

### 6.1 가림 집합을 넣는 것이 M5d 와 충돌하지 않는 이유

M5d 는 가림을 DB 에 쓰지 않기로 했고 근거는 **"훼손은 지도의 사실이 아니라 그 순간의 사정"** 이었다. `localStorage` 는 정확히 *보는 사람* 쪽이므로 그 결정과 같은 방향이다. 지도는 여전히 마커를 약속하고, 이 브라우저만 그것을 못 본다.

### 6.2 저장하지 않는 것

선택된 객체는 저장하지 않는다. 새로고침 후 어제 고르던 마커가 선택돼 있고 속성 탭이 열려 있으면 혼란스럽다. 선택은 매번 비운 채로 시작한다.

## 7. 테스트

### 7.1 단위 (Vitest)

1. `ui.ts` 저장·복원 왕복 — 스키마 버전이 다르면 기본값
2. 탭 전환 규칙 — 선택이 생기면 속성으로, 해제하면 직전 탭으로
3. 평면도 확대·이동 변환 (화면 좌표 ↔ Ship Frame)
4. 범례의 색이 `cellColor` 와 같은 값을 쓴다 (두 벌이 갈라지지 않게)
5. 단축키 매핑 — 입력 필드에 포커스가 있으면 단축키가 먹지 않는다

### 7.2 단위 (Unity EditMode)

1. **선택 모드에서는 생성되지 않는다** — 구조물을 클릭해도 `Created` 가 발화하지 않는다
2. **배치 모드에서는 생성된다** — 같은 클릭이 마커를 만든다
3. `VisibleFrom` 이 `Sense` 와 같은 집합을 낸다 — 노이즈 0 에서 두 결과가 일치
4. `VisibleFrom` 이 `occluded` 를 존중한다
5. 법선 기즈모가 각을 `(-π, π]` 로 감는다 — `atan2(-0.0, -1)` 함정(M5c §5.1.1)
6. 관측점 자세의 가시 집합이 세 조건을 각각 반영한다 (거리·시야각·법선 하나씩 위반시키면 빠진다)

### 7.3 브라우저 검증

1. 편집 모드에서 3D 를 회전·클릭해도 마커가 생기지 않는다. 배치 모드로 바꾸면 생긴다
2. 트리에서 마커를 고르면 3D 가 그리로 가고 속성 탭이 뜬다. 삭제 버튼으로 지워진다
3. 기즈모로 법선을 90° 돌리면 히트맵과 `blind_ratio` 가 바뀐다
4. 새로고침 후 탭·갑판·슬라이더·카메라·도크가 그대로다
5. 자유 비행으로 갑판을 돌아다닌다. 캔버스 포커스가 없으면 키가 안 먹고 그것이 보인다
6. 하역 주행을 차량 시선으로 본다. 선미에서 마커가 하나씩 꺼지고 마지막이 꺼질 때 상태가 `상실` 이 된다
7. 관측 모드로 바깥 열 구획에 관측점을 찍으면 보이는 마커가 적고, 차로에 찍으면 많다
8. 평면도를 확대해도 3D 는 그대로다 (뷰포트 독립)

## 8. 결정과 이유

| 결정 | 이유 |
| --- | --- |
| 평면도를 하단 전폭으로 | 갑판이 5:1 가로 그림이다. 좁은 칼럼에서는 확대 없이 못 읽는다 |
| 오른쪽을 탭으로 | 패널 넷이 쌓여 스크롤이 길다. 한 번에 하나면 무엇이 중요한지 화면이 말한다 |
| 선택 시 속성 탭 자동 전환 | 탭으로 묶으면서 이걸 빠뜨리면 지금보다 나빠진다 |
| 배치 모드를 고정으로 | 줄지어 놓는 것이 실제 작업이다. 우발적 생성은 모드를 몰라서 생기지 고정이라 생기지 않는다 |
| 삭제를 버튼 하나로 | undo 가 없는 동안 되돌릴 수 없는 동작을 키에 두지 않는다 |
| 법선을 항상 그린다 | 기즈모를 만들면서 그 효과가 안 보이면 절반만 만든 것이다 |
| 가시 판정을 한 곳에서 | `Sense` 와 표시가 갈라지면 화면이 거짓말을 한다. M5d 가 같은 이유로 야코비안을 공유했다 |
| 차량 시선에 콘과 호를 | 마커가 꺼진 것만 보이고 왜 꺼졌는지는 안 보인다. 세 조건 중 둘을 그리면 나머지 하나가 소거법으로 드러난다 |
| 관측점을 편집 모드에 | 마커를 놓고 나서 "여기서 뭐가 보이나"가 자연스러운 질문이다. 히트맵보다 직관적일 수 있다 |
| 화면 상태를 브라우저에 | 보는 사람의 것이다. DB 는 스키마와 "누구의 프리셋인가"를 불러온다 |
| 선택은 저장하지 않음 | 새로고침 후 어제 고르던 것이 선택돼 있으면 혼란스럽다 |
| 3D 히트맵 없음 (유지) | M5c 의 결정을 뒤집지 않는다 |

# M8 설계 스펙 — 5개 갑판, 내부 램프, 전 갑판 주차 (2026-09-28)

기본 스펙 `2026-09-15-ship-hdmap-demo-design.md` 와 M7 다음 단계. 용어는 [용어집](../../glossary.md), 근거는 [설계 근거 §7.2](../../design-rationale.md) 참조.

---

## 1. 범위

### 1.1 목적

M7 까지는 갑판 3개 중 D3 만 썼다. 선미 램프 하나가 D3 에 닿고, 코드가 `ramps[0]` 을 선미 램프로 가정했다. 구획 생성과 래싱점 내보내기도 D3 만 했다. 선체는 갑판 바닥과 벽뿐이었다.

목표는 자동차운반선(PCTC)다운 모델이다. 5개 갑판, 가변 내부 램프, 모든 갑판의 주차 구획과 래싱을 갖춘다. MEP(배관)는 뺀다.

### 1.2 확정 결정

| 항목 | 결정 |
| --- | --- |
| 선미 램프 | D3(가운데)에 닿는다. 내부 램프는 좌현 D3→D2→D1, 우현 D3→D4→D5 |
| 가변 램프 | 호이스트형, 전개·수납 두 상태 |
| 선체 | 절차적 PCTC 외형 + 단면 보기(기본) |
| 적재 순서 | 먼 갑판부터 D1 → D5 → D2 → D4 → D3, 하역은 역순 |
| 선체 평면 | 120 × 24 m 유지 (기존 수치와 비교 가능) |
| MEP | 제거 |

## 2. 기하 (Ship Frame: x 선수+, y 좌현+, z 기선 위)

- 갑판 `D1..D5`, z 5.4 / 8.0 / 10.6 / 13.2 / 15.8 (층고 2.6 m).
- 내부 램프: 길이 20 m, 폭 4 m, 경사 7.47°. 선측 띠 중심 y ±9.8 (기둥 열 y ±6.5 와 겹치지 않음). 힌지는 위층 끝.

| 램프 | 선측 | 윗끝(힌지) | 아랫끝 | 가까운 쪽(수납 시 구획) | 먼 쪽(항상 주차 불가) |
| --- | --- | --- | --- | --- | --- |
| `RAMP-D3-D2` | 좌현 | D3 x 34 | D2 x 14.17 | D3 구멍 자리 | D2 착지 자리 |
| `RAMP-D2-D1` | 좌현 | D2 x 56 | D1 x 36.17 | D2 구멍 자리 | D1 착지 자리 |
| `RAMP-D3-D4` | 우현 | D4 x 14.17 | D3 x 34 | D3 착지 자리 | D4 구멍 자리 |
| `RAMP-D4-D5` | 우현 | D5 x 36.17 | D4 x 56 | D4 착지 자리 | D5 구멍 자리 |

- 경로 `ROUTE-D1/D2/D4/D5`: D3 입구 (2, 0, 10.6) 에서 목표 갑판 주 차로 시작점 (8, 0, z) 까지의 3D 폴리라인. U턴 반경 4.9 m(기둥 사이, 운동학 시뮬레이션이라 허용). D3 는 경로가 없다.
- 주 차로: D3 는 x 2→118(기존과 같음), 나머지는 x 8→118.
- 검사(EditMode): 경로 차체 스윕이 기둥·벽과 겹치지 않는다, 경사 ≤ 8°, 경로의 `ramps` 가 실제로 지나는 램프와 같다, 입구와 차로 시작점을 잇는다.

## 3. 데이터 모델 (vehicle-map v1 호환 확장)

- `Ramp`: `type` `stern_quarter | internal_hoistable`, 내부 램프만 `lower_deck`, `upper_deck`, `toe`(아랫끝 두 점).
- `VehicleMap.routes`: `{id, deck_id, ramps, path}`.
- DB 스키마 변경 없음. 경로는 `A2` kind `route`(LineStringZ), 램프 새 필드는 `C/ramp` props.
- 구획 `sequence_no` = 갑판 순위 × 1000 + 갑판 안 순번. 순위는 선미 램프 갑판에서 먼 순, 같으면 아래층 먼저. 갑판 안은 기존 선수 우선.
- 구획 생성: 이 갑판 위 경로 구간을 회랑에 더하고, 먼 쪽 램프 자리를 장애물로 둔다. 가까운 쪽 자리는 허용한다.
- 커버리지: 경로 구간을 분석 대상에 포함한다.

## 4. 주행

- 단계: 적재 `… → OnRoute → OnLane → Parking`, 하역 `Departing → ReturnRoute → 부두`.
- 경로는 차로처럼 정확히 추종한다. 믿음 판정은 `OnLane`·`Parking`·`Departing` 에서만.
- 램프 규칙(`RampPlanner`): 목표 경로의 램프는 출발 전에 전개한다(가까운 쪽 자리에 차가 없을 때만). 전개된 램프는 먼 쪽에 남은 빈 구획이 없으면 수납한다. 조건을 못 맞추는 구획은 이번 차례에 건너뛴다.
- 예측 격자는 갑판별(`SetPrediction.deck_id`)로 보관하고 차량이 있는 갑판 것을 쓴다.
- 브리지: `SetRampState`(편집 모드에서만), `SetShellMode(cutaway|full)`. 이벤트 `route`, `lane`, `ramp`.

## 5. 표현

- `HullBuilder`: 트랜섬(선미 램프 개구), 건현 3색 도장, 빌지, 선수와 구상선수, 지붕, 브리지·윙·마스트, 굴뚝. 콜라이더 없음. 양면 메시는 뒷면 정점을 따로 둔다(공유 정점이면 법선이 0 이 되어 NaN 조명).
- 갑판 바닥은 램프 구멍을 뺀 메시 + MeshCollider. 래싱 소켓은 갑판당 결합 메시 하나. 주차 차량에 래싱 스트랩 4개.
- 갑판 필터: 선택 갑판보다 위층과 머리 위 램프를 숨긴다.
- 웹: 갑판 단축키 1~5, `전 갑판 생성`, 램프 패널(상태 배지·토글), 평면도의 램프 자리 빗금과 경로 구간.

## 6. 결과 (재현 캡처 기준)

- 픽스처: 5 갑판, 랜드마크 107, 래싱점 23,610, 시설물 90, 램프 5, 경로 4.
- 구획: D1 66, D2 66, D3 66, D4 65, D5 66 = 329, 래싱 커버리지 100 %.
- 알려진 한계: 내부 램프 띠 위에서는 보이는 마커가 0 개라 추정이 이전 값에 머문다. 목표 갑판 차로에서 회복한다(오차 약 0.2 m).
